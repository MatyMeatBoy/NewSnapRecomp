# Version 0.4 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans or scoped parallel workers to implement each independently testable task.

**Goal:** Implement owner-local update maintenance and verified temporal upscaling with individual quality presets.

**Architecture:** Retain the hash-bound private runtime and public launcher separation. Build candidate runtimes from existing owner imports, validate them before switching, and preserve previous usable outputs. Feed graphics providers through an explicit Snap scene contract; provider discovery alone never enables temporal rendering.

**Tech Stack:** Python, C, Vulkan, SDL, pinned Astral donor, official AMD FSR Vulkan SDK and NVIDIA NGX where supported.

**Spec:** `docs/ROADMAP.md`, Owner targets for v0.4.

## Global Constraints

- Preserve owner saves, imported data and configuration; never distribute proprietary inputs or generated game code.
- Keep the released 0.3 archive immutable.
- Use verified Snap buffers/camera data, never donor game offsets.
- RX 6900 XT model support follows the actual official provider; no guessed INT8 overrides.
- Native/spatial rendering remains available when temporal inputs or providers are unavailable.

## Review Focus

- Failed or cancelled rebuild preserves the usable runtime and saves.
- Same-version updates detect actual recipe and capability differences.
- Missing DLLs, exports, device features or providers produce an accurate fallback.
- Scene changes, photo mode and loading reset temporal history and preserve photograph correctness.
- Presets reflect actual provider support and distinguish requested from active backend.
