# CRC32 ISA acceleration implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Keep the published alpha and owner data immutable.

**Goal:** Reduce the cost of the observed resource CRC32 workload while preserving every ARM instruction result and resource validation.

**Architecture:** Optimize the existing IEEE CRC32 ISA macro with portable slicing-by-eight tables for four/eight-byte inputs. Keep the original scalar helper as a startup-selectable reference path; leave CRC32C, scheduling and game logic unchanged. No additional host CPU feature requirement. Diagnostic work identified a checksum workload, not a universal explanation of every frame spike.

**Tech stack:** Existing Python source adapters, C runtime overlays/headers, clang native fixtures and private game-data oracles. Main is the integration branch; no version branches or mutation of the donor submodule.

## Evidence and constraints

- Baseline: published-alpha public-kit build, SHA256 `e0dcac87a708d1f5f7c5a0cf880525784a8ae077f06c1b37c67f4166045b8db4`.
- Fresh diagnosis: `build/v05-alpha-corediag-01/`, original installation preserved.
  Long-wait samples include CRC at main+0x15fe90 and the resource RNG worker.
  Sampling proportions are not CPU-time percentages; CORE_DIAG interrupts owners.
- Current host is on battery (ACLineStatus=0, 26% when checked). Do not compare
  absolute timings against earlier measurements with unrecorded power conditions.
- User excluded recovery of the old profile; their RX 6900 XT test remains pending.
- CRC32 IEEE uses reflected polynomial `0xedb88320`. x86 CRC32C is a different
  polynomial and cannot substitute it. Do not skip or weaken checksum validation.
