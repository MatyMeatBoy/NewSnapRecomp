# Version 0.5 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans or scoped independent workers; verify each task before integration.

**Goal:** Improve display/controller observability and reduce repeated private code-generation work while preserving neutral Snap rendering.

**Architecture:** Optional native display observations feed a small versioned status contract. A launcher-owned SDL controller session operates under the existing runtime/profile exclusion. The rebuilder restores only hash-verified generated code from a bounded local cache.

**Tech Stack:** C, Vulkan, Windows display APIs, SDL3, Python/Tk and existing provenance receipts.

**Spec:** `docs/V05.md`.

## Global Constraints

- Released 0.4 archives, tag and source kit remain immutable.
- Preserve original SDR grading, 100% Native AA/DLAA and native 30/60 FPS limits.
- No guessed VRR state, game-data distribution, save edits or unvalidated cached executables.
- Missing optional hardware APIs retain normal rendering and honest unknown status.

## Review Focus

- Stale monitor/swapchain observations must not survive a recreation.
- A sync mode or nominal refresh rate does not establish VRR operation.
- Controller loss/initialization failure must release SDL and launcher ownership.
- Cache corruption or a recipe mismatch must regenerate, rather than reuse.
- Cache cleanup must be bounded to its verified local directory.
