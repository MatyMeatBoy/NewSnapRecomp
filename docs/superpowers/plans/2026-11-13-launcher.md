# Launcher and Photo Album Implementation Plan

**Goal:** provide the requested desktop launcher, video controls, real-photo album and icons while fixing confirmed input defects.
**Architecture:** Tkinter UI, separate settings/photo backends, original reproducible icons; pinned runtime overlays remain isolated.
**Tech Stack:** Python 3.12, Tkinter, Pillow, native C input/runtime.

- [x] Launcher: implement tabs, nonblocking launch/preparation, profile paths and safe persistence of verified runtime settings. Test settings validation and preservation.
- [x] Icons: create original SVG/PNG/ICO/favicon variants with a reproducible generator; inspect appearance and dimensions.
- [ ] Photos: identify the game's format, implement bounded read-only extraction and test valid/truncated/duplicate data. Connect real captures to the UI.
- [ ] Input: reproduce neutral versus moved mouse/stick, inspect gyro path and capture transitions, fix only demonstrated defects. Validate photo aiming.
- [ ] Runtime: complete device-time API regression and continue tutorial/photo capture.
- [ ] Integrate: inspect desktop UI, run source/content checks and tests, review, commit and push coherent blocks.

The owner's direct-action preference persists; implementation choices above are
engineering defaults, not additional user requirements. Asset and launcher work
can proceed independently of the input investigation with the Photos API fixed
in docs/design-launcher.md. Never overwrite another worker's files.
