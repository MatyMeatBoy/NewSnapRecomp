# Version 0.4 alpha

This candidate adds temporal scene reconstruction and owner-local rebuilds after
launcher updates. The 0.3 release archives remain immutable.

## Neutral color output

Snap retains its own colors, lighting, tone mapping and SDR transfer. The port
adds no brightness, contrast, saturation or gamma adjustment, including when an
old INI/environment requests an Astral color profile. Added HDR conversion, AO,
contact shadows, PCSS, shadow-map enlargement and RCAS sharpening are disabled.
Final window scaling is bilinear. Native AA/DLAA remains a reconstruction option;
the original game rendering is also available.

Inherited 80% RCAS and 2x shadow enlargement were active donor defaults. The
reduced-resolution temporal path could also sharpen linear scene light before
Snap's final tone map. That extra stage is disabled; the game's final RGBA8
output is not gamma-encoded a second time. This does not establish pixel identity
with a physical Switch/monitor setup.

## Reconstruction

- Official AMD FSR SDK 2.4.0 Vulkan provider, with explicit FSR 3.1 and FSR 4
  selection. FSR 3.1.6 has executed in Snap on the local RTX 4060. FSR 4 follows
  the actual queried provider and enabled device features; RX 6900 XT hardware
  validation remains pending. Compatible RX 6000/7000 INT8 model selection is
  handled by AMD's provider, without guessed model overrides.
- NVIDIA DLSS Super Resolution 310.9.16, with real NGX availability checks.
  Native mode uses DLAA. This does not add frame generation.
- Individual backend selection with **Native AA / DLAA**, Quality (70%),
  Balanced (60%) and Performance (50%). Native always selects the engine's 100%
  scene. These are Snap's verified graph sizes, rather than arbitrary resizes of
  Vulkan images. The original rendering option remains available.
- Auto prefers available DLSS, then FSR 4, then FSR 3.1. A requested unavailable
  backend retains a compatible fallback. The runtime performance display reports
  a temporal backend only while it actually resolves frames.
- Snap camera c3 is 0x2e8 bytes: column-major view, inverse view, projection,
  inverse projection, view-projection and inverse view-projection. The adapter
  normalizes and validates matrix products before temporal history can use them.
  Actual first-course captures show reversed infinite-Z, near 0.01, and linear
  RGBA16F scene color before the final RGBA8 tone-map/HUD pass.
- Scene/HUD separation, camera/object reprojection, viewport jitter and history
  resets reuse the portable donor machinery with Snap-specific contracts.
  SDK input layouts are transitioned explicitly and restored afterward; context
  lifetime follows the last recorded GPU fence.

## Updating and rebuilding

- The public launcher continues to update or repair the same installed stable
  release from the canonical GitHub repository.
- A runtime version, capability, executable/support-file hash or source-recipe
  mismatch schedules a local rebuild. The build kit must match the installed
  release's exact source revision, including for a same-version repair.
- The kit contains original public sources, portable Python/compiler, native
  shader headers, pinned graphics providers and their licenses. It contains no
  game imports, keys, saves or generated game code.
- Original ExeFS and RomFS hashes are checked before generation. Candidate
  outputs pass native selftest and loader checks before being switched into
  GameData. Profile, settings, recordings and unrelated files are preserved.
- Failed/cancelled builds retain the usable runtime. A journal and verified
  backups support interrupted-switch recovery. Shader preparation is required
  after a successful runtime rebuild before the next expedition.

## Validation scope

The portable owner rebuild has completed generation of 62,961 functions and
compilation of 275 objects, passed both candidate probes and preserved isolated
save/settings/unrelated-file sentinels. Native-resolution DLSS and official
FSR 3.1 have resolved real moving scenes on the RTX 4060.

The first DLSS trial encountered a nondeterministic CPU texture upload fault;
an identical 90-second repeat passed. A separate native regression proved that
retired pool descriptors could recreate stale images; the adapter now invalidates
overlapping descriptors after replay drain. That proven fix does not alone
establish causality for the original fault. Longer acceptance results and the
final artifact receipts are recorded separately.

Full-game scene coverage, moving foliage/transparency quality, all photo/zoom
transitions and physical AMD/controller coverage remain broader acceptance work.
No gameplay FPS improvement is claimed from these tests.
