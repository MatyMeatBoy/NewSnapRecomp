# NewSnapRecomp 0.1.1 alpha

MatyMeatBoy's experimental alpha update for Windows x64 (a CPU with AVX2 and a Vulkan driver). Not
a complete port or a stable version.

## Included

- Verified import of your own base and 2.0.1 update.
- A launcher in Spanish: profiles, shader preparation, controls and album.
- Basic and advanced video: custom window, fullscreen, TV/handheld output, native internal scale
  50–100 %, spatial/bilinear FSR, sharpness, anisotropy, fit, brightness, contrast, saturation and
  gamma.
- 30/60 presentation caps and FIFO, mailbox, immediate and relaxed FIFO modes with a fallback. VRR
  depends on the system; more than 60 FPS is still under investigation.
- A local name without Nintendo's word dictionary, device time settings, close protection while
  saving and a supervised restart.
- Original camera icons and favicon variants.

## Checked and pending

The local build, the memory/dispatch self-test and the loader test pass. Isolated tests reach the
3D scene and the camera tutorial. GPU telemetry confirms render-size changes at 50/100 % without
recorded errors in those probes. This does not vouch for every path or sustained performance.

A complete route, evaluation/scoring, persistence of real photos, long sessions and other GPUs
remain unverified. The album reader has tests with synthetic photos and real headers of empty
banks. Two geometry shader entries are unsupported. DLSS, XeSS, temporal FSR, HDR and the base's
specific shadow effects are not advertised as features adapted to Snap.

## Packages

The GitHub asset contains sources, tools and the pinned base; it needs your own files and a local
build following the README. It excludes data, keys and game-derived executables.

The private package requested for another PC is delivered only as a local file: it includes the
test executable, Python, dependencies, already imported data and a copy of the local profile.
Extract everything and open **Iniciar NewSnap.cmd**. The shader cache is rebuilt for the target
GPU. Running on that second PC is still to be tested. Keep the original profile and use the copy
to test.

## Move fix from 0.1

The launcher now saves profiles inside its folder as relative paths: when the whole folder is
moved, the profile follows the application. External profiles keep their explicit path. Relative
preferences that escape the folder and JSON with an invalid structure are rejected with a fallback
to the local profile. A test reproduces the earlier failure when renaming the folder and checks
the fixed behaviour.

The portable check with PATH limited to Windows System32 passes the dependency imports, loads Tcl
from the package and starts the runtime with the copied data. It does not depend on this PC's
installed LLVM/MSYS or Python for those checks. The second physical PC is still untested.

The packages carry the revision in their name and a hash manifest. The `d0d8a66b` source asset
predates this fix; use the asset with the revision named as fixed in the release description.
