# NewSnapRecomp 0.3 alpha

This delivery gathers the improvements already implemented and checked. It is still an alpha;
FSR 4/INT8, temporal FSR 3.1 and DLSS are goals for 0.4.

## Included

- Launcher updater from GitHub's latest **stable**, with private repository access,
  SHA-256/manifest validation and a restart outside the installed folder. It can update or repair
  the same version. It keeps your own data, profiles, settings and files outside the package.
  Alphas are not picked as stables.
- A compatibility check of the private runtime: updating the launcher does not present an old
  runtime as if it included all the new improvements.
- Optional SDL mappings for generic controllers, keeping the user's remaps. Native tests of
  Xbox/PlayStation/Nintendo layouts and virtual reconnection; physical models still pending.
- Shader preparation that restores the previous valid record if the new attempt fails. On cancel,
  the producer ends before restoring.
- Adaptation of the Snap SDK's non-local jumps: fixes the block reproduced after evaluating the
  tutorial's photo. It keeps the return points and register state; it rejects invalid contexts
  and jumps across unsupported host services.
- An album with real photos extracted from verified saves. It groups the thumbnail with its
  original; it keeps the thumbnail if there is no original. Export without recompressing the
  photo.
- A language selector limited to those declared by this version of Snap, including Spanish and the
  Latin American Spanish preference. The game has its own text and voice settings: an existing
  profile may keep its language and need changing inside the game too.

It keeps 0.2's video/audio/control options, TV mode by default and experimental 125/150/200 %
supersampling in TV only. The current FSR is spatial.

## Evidence and limits

Isolated test on an RTX 4060: nine minutes, 32,263 presents, zero unimplemented NVN calls,
validation errors, shader failures or skipped draws. It captured Pikachu, showed 2,600 points,
passed the old block and entered the first route. Seven save files changed. The reader got two
1080×720 originals and their thumbnails; the originals opened and exported with identical bytes.
The prior preparation created 3,520 supported variants without translation or driver preparation
failures. It does not vouch for the variants or pipelines of the whole game, equivalent
performance or the absence of hitches.

Packaged update: the frozen 0.2 worker → 0.3 candidate and a repair of the same version were
tested, verifying 1,101 files and keeping data/INI sentinels. The real authenticated download from
GitHub also passed its hash. The final package's identity and later checks are recorded when this
release is closed.

Pending: a complete route with evaluation and reloading its photos; photos at every scale; >100 %
scaling in handheld; two geometry shaders; AMD and other physical controllers; long
sessions/protected close; more than 60 FPS and the temporal upscalers. A complete runtime rebuild
from the launcher is left for 0.4. Other GPUs' stability is not deduced from the RTX 4060 test.

## Install and update

Extract the whole Windows ZIP and keep `_internal`. Put your `GameData` or `newsnapGameData` next
to **NewSnapLauncher.exe**. Python does not need installing. The public ZIP contains neither the
game nor its private executable.

To benefit from this version's native fix, also update the private runtime to 0.3. If you already
played on another PC, keep its `profile` folder and its settings; replace only the runtime files
the private delivery names. Do not overwrite saves with another installation's profile. Prepare
graphics on each GPU/driver. Requirements: Windows x64, an x86-64-v3 CPU and Vulkan 1.3 with the
capabilities the backend requires.
