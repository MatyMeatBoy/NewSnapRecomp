# NewSnapRecomp 0.9.30

- **Prepare graphics on Vulkan without GPL.** The preparation command warms
  previously recorded whole graphics pipelines and saves their Vulkan cache
  before gameplay. The existing boot prewarm uses that cache. New pipeline
  recordings and changes to GPL settings invalidate the preparation receipt.
- **Vulkan pipeline libraries (GPL)** has a selector in the launcher's Video
  settings. Automatic follows the driver policy and leaves GPL off on the AMD
  RDNA 1/2 driver branch. Enabled is experimental and requires Vulkan fast
  linking support. Disabled uses whole pipelines.
- The owner confirms the shadows look correct on the RX 6900 XT.

## Checked on RTX 4060 Laptop

With GPL disabled and the same 243 recorded shaders, standalone preparation
built 128 whole graphics pipelines in both passes, with zero failures or
drops. The Vulkan cache was written before the game started. The original
pipeline keys and gameplay shader recordings were preserved. With GPL
enabled, stage-library preparation ran and the new whole-pipeline pass
was skipped.

Two matched pairs at a 144 FPS cap, 1280×720 window, 1920×1080 internal,
without upscaling, frame generation or HD shadows, used copies of the same
profile and reversed run order. The boot pipeline phase took **171 → 49 ms**
and **206 → 33 ms** with the prepared cache. Total boot time varied across
the pairs. The driver's separate persistent cache was not reset.

During the same right-turn interval, p99 was **24.99 → 11.79 ms** in the
first pair and **11.14 → 11.69 ms** in the reverse pair. Frames over 25 ms
were **16 → 1** and **0 → 0**. The four turn samples recorded zero shader
translation and pipeline-build wait time. The camera result varied by
pass, so the preparation change does not establish a camera-pacing fix.
